1.3 Why hill climbing is not enoughMengapa pendakian bukit tidak mencukupi

Hill climbing accepts a neighbour only if it is at least as good. It stops at a local optimum: a solution with no better neighbour, although a better solution exists elsewhere (the global optimum). The landscape image helps: the height is solution quality, and the neighbourhood decides which points are "next to" each other. Change the neighbourhood and you change the landscape.

Pendakian bukit menerima jiran hanya jika ia sekurang-kurangnya sama baik. Ia berhenti pada optimum setempat: penyelesaian tanpa jiran yang lebih baik, walaupun penyelesaian lebih baik wujud di tempat lain (optimum sejagat). 2.1 Where the idea comes fromAsal usul idea

Metallurgists anneal metal by heating it until atoms move freely and then cooling it slowly, so the atoms settle into a low-energy crystal. Cooling too fast (quenching) freezes defects in place. In 1953 Metropolis and colleagues proposed a rule to simulate such systems on a computer Metropolis et al. 1953. Thirty years later, Kirkpatrick, Gelatt and Vecchi Kirkpatrick et al. 1983, and independently Černý Černý 1985, turned the rule into a general optimiser and applied it to chip placement and the travelling salesman problem.

Ahli metalurgi menyepuhlindap logam dengan memanaskannya sehingga atom bergerak bebas, kemudian menyejukkannya perlahan-lahan supaya atom mendap ke hablur bertenaga rendah. Penyejukan terlalu cepat (lindap kejut) memerangkap kecacatan. Pada 1953, Metropolis dan rakan-rakan mencadangkan peraturan untuk menyimulasikan sistem sebegini pada komputer Metropolis et al. 1953. Tiga puluh tahun kemudian, Kirkpatrick, Gelatt dan Vecchi Kirkpatrick et al. 1983, dan secara berasingan Černý Černý 1985, menjadikan peraturan itu pengoptimum umum dan menggunakannya untuk penempatan cip dan masalah jurujual kembara.

2.2 The Metropolis acceptance rulePeraturan penerimaan Metropolis

For minimisation, let Δ = f(s′) − f(s). If Δ ≤ 0 the neighbour is no worse, so accept it. If Δ > 0, accept it with probability:

Bagi peminimuman, biar Δ = f(s′) − f(s). Jika Δ ≤ 0 jiran tidak lebih buruk, maka terima. Jika Δ > 0, terima dengan kebarangkalian:

P(accept) = exp(−Δ / T) accept if r < P, r ~ Uniform(0, 1)

Read the formula as two dials. A larger worsening Δ lowers P. A higher temperature T raises P. For maximisation use Δ = f(s) − f(s′) so that Δ is still positive for a worse move.

Baca formula sebagai dua tombol. Kemerosotan Δ yang lebih besar merendahkan P. Suhu T yang lebih tinggi menaikkan P. Bagi pemaksimuman gunakan Δ = f(s) − f(s′) supaya Δ masih positif bagi langkah lebih buruk.

Common mistakesKesilapan lazim
  • Using a T₀ unrelated to the cost scale. T must be in the same units as Δ: a T₀ of 10 is "hot" for costs near 50 and "frozen" for costs near 50,000.

  • Memulangkan penyelesaian akhir dan bukan yang terbaik setakat ini.
  • Comparing SA with another method on different budgets. Compare on equal numbers of evaluations.
  • Membandingkan SA dengan kaedah lain pada bajet berbeza. Bandingkan pada bilangan penilaian yang sama.

3.3 Setting the decay rateMenetapkan kadar susutan

ΔB = (f₀ − f*) / N e.g. f₀ = 120, f* = 80, N = 200 → ΔB = 0.2 per move

Two questions replace temperature tuning: How long can you run? (N) and What result would you accept? (f*). Burke and colleagues called this a time-predefined search: the user trades time for quality explicitly Burke et al. 2004.

Dua soalan menggantikan penalaan suhu: Berapa lama boleh dijalankan? (N) dan Keputusan apa yang boleh diterima? (f*). Burke dan rakan-rakan menamakannya carian masa pratakrif: pengguna menukar masa dengan kualiti secara jelas Burke et al. 2004.

Two ways to get the target wrongDua cara salah menetapkan sasaran
  • Too optimistic (f* below what is reachable): the level falls below the current cost early, after which only improvements pass. GD turns into hill climbing for the rest of the run.
  • Terlalu optimis (f* di bawah yang boleh dicapai): paras jatuh di bawah kos semasa lebih awal, selepas itu hanya penambahbaikan lulus. GD menjadi pendakian bukit untuk baki larian.
  • Too pessimistic (f* far above the optimum): the level stays loose, the search keeps wandering, and it finishes near f*, not near the optimum.
  • Terlalu pesimis (f* jauh di atas optimum): paras kekal longgar, carian terus merayau, dan berakhir hampir f*, bukan hampir optimum.

      import math, random

def f(x):                       # objective to MAXIMISE on [0, 10]
    return x * math.sin(x)

def neighbour(x, step=1.0):     # small random move, kept inside [0, 10]
    return min(10, max(0, x + random.gauss(0, step)))

def hill_climb(x, iters=1000):
    for _ in range(iters):
        y = neighbour(x)
        if f(y) >= f(x):
            x = y
    return x

def simulated_annealing(x, T0=10.0, alpha=0.995, iters=1000):
    T, best = T0, x
    for _ in range(iters):
        y = neighbour(x)
        delta = f(x) - f(y)                     # > 0 means y is worse
        if delta <= 0 or random.random() < math.exp(-delta / T):
            x = y
        if f(x) > f(best):
            best = x
        T *= alpha                              # geometric cooling
    return best

def great_deluge(x, level=-6.0, target=7.9, iters=1000):
    rain = (target - level) / iters             # how fast the water rises
    best = x
    for _ in range(iters):
        y = neighbour(x)
        if f(y) >= f(x) or f(y) >= level:
            x = y
        if f(x) > f(best):
            best = x
        level += rain
    return best

random.seed(42)
for name, algo in [("HC", hill_climb), ("SA", simulated_annealing), ("GD", great_deluge)]:

    print(f"{name}: reached the global peak in {wins}/100 runs; last run x={xb:.3f}, f={f(xb):.3f}")

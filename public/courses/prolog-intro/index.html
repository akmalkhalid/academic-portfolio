Imperative vs Declarative

Python · HOW 
parents = [("ali","aminah"), ("aminah","danial")]

Prolog · WHAT 
parent(ali, aminah).

grandparent(G, C) :- parent(G, P), parent(P, C).
grandparent(G, C).G = ali,\nC = danial.
You state facts & logic. Prolog searches for answers.
Same problem, two mindsets. In Prolog there is no loop and no print. The search is built into the language. Ask: "Which one reads closer to English?"
The whole idea in one picture

Knowledge + Question → Proof

Prolog = PROgramming in LOGic. You give it a knowledge base and a question. The engine tries to prove the question from the knowledge. If it can, it answers with the variable values that made it true.

One data type to rule them all

Everything is a term

Reveal the tree branch by branch. Constants are fixed values; variables are unknowns; compound terms are structures built from a name plus arguments.
Constants · names of things

Atoms start lowercase

a
lowercase letter first: ali nasi_lemak tk2313
'
anything in single quotes: 'Kuala Lumpur' 'Ali'
+
symbol sequences: + =.. []
❌ Ali is not an atom, it is a variable!
❌ nasi lemak has a space. Use nasi_lemak.
atom(ali).true.
atom('Kuala Lumpur').true.
atom(Ali).false.
Let students predict the third one before revealing: Ali with a capital A is a variable (unbound), so atom(Ali) is false.
Unknowns to be found

Variables start Uppercase or _

_
Anonymous _ means “I don't care what it is”

A variable gets a value once: no X = X + 1 like in Python
↻

X = 5, X = 6.false.

Requires the demo file to be loaded for the last query. X = 5, X = 6 is false because X is already 5: variables are not boxes you overwrite. The last query answers "does ali have any child?" without naming it; it is true twice (aminah, badrul).

Queries · ask a question

Yes/no questions → true / false

parent(ali, aminah).true ;\nfalse.
parent(aminah, ali).false.
male(hana).false.
Closed world: if Prolog can't prove it from the program, the answer is false. It does not mean “impossible”, only “not known”.
Why true ; then false?
Prolog found it but still had another parent(ali, …) fact to try. Press ; to check it: no more, so false. Press Enter to stop instead.
Run the first query: SWI prints "true" and waits. Press ; to show the false. Explain the choice point. It is normal, not an error.
Queries · let Prolog find values

Variables ask “who?” / “what?”

parent(ali, X).X = aminah ;\nX = badrul.
parent(X, danial).X = aminah.
likes(Who, nasi_lemak).Who = aminah ;\nWho = danial.
after each answer
;
next answer
(backtrack)
Enter
stop, I'm happy
Translate: “Is there an X such that ali is a parent of X?”
Emphasise reading a query aloud as a question with "there exists". Let the students press ; themselves on the lab PCs.
Comma , = AND

Combine goals with ,

parent(ali, X), female(X).X = aminah ;\nfalse.
parent(siti, P), parent(P, G).P = aminah,\nG = danial ;\nP = badrul,\nG = farah.
The same variable links the goals: the X found in goal 1 must also pass goal 2.
Query 2 = “grandchildren of siti”. We'll turn it into a reusable rule next.
Read query 1 aloud: "a child X of ali, AND X is female". The trailing false comes from trying badrul (male) after the first answer.
Rules · knowledge that depends on other knowledge

Anatomy of a rule

father(F, C) :- parent(F, C), male(F).
HEAD
the conclusion
:- IF
“is true if”
BODY
conditions, joined by , = AND
🗣 “F is the father of C if F is a parent of C and F is male.”
A fact is a rule with an empty body (always true). Facts + rules = Horn clauses: head :- body.
Live demo · rules in the demo file

Family rules

father(F, C)      :- parent(F, C), male(F).
mother(M, C)      :- parent(M, C), female(M).
grandparent(G, C) :- parent(G, P), parent(P, C).
sibling(X, Y)     :- parent(P, X), parent(P, Y), X \= Y.
🤔 Why does badrul appear twice?
Aminah and Badrul share two parents, so it is proved once via ali and once via siti.
father(F, aminah).F = ali ;\nfalse.
grandparent(ali, Who).Who = danial ;\nWho = farah.
sibling(aminah, S).S = badrul ;\nS = badrul.
X \= Y means "X does not unify with Y", so nobody is their own sibling. Let students try removing it (in the file, then make.) to see aminah become her own sibling. The duplicate answer is a great discussion: Prolog finds every PROOF, not every unique value.
Two ways to say OR

OR = ; or several clauses

guardian(G, C) :- parent(G, C).
guardian(G, C) :- grandparent(G, C).
guardian(ali, C).C = aminah ;\nC = badrul ;\nC = danial ;\nC = farah.
Same meaning, one clause:
guardian(G,C) :- parent(G,C) ; grandparent(G,C).
parent(ali, X) ; parent(danial, X).X = aminah ;\nX = badrul ;\nX = hana.
Prefer separate clauses: easier to read and debug.
Prolog tries clauses top to bottom; each clause is an alternative way to prove the head.
NOT

\+ = “cannot be proved”

\+ male(siti).true.
\+ parent(hana, _).true.
Negation as failure: \+ G succeeds if G fails.
Also written not(G).
Query 2: “Hana has no children” is true because no fact says she has.
Keep brief; this is covered in more depth in the lab (Exercise 4).

Most common confusion

Four kinds of “equal”

=unify (pattern match)X = 1 + 2X = 1+2 no maths!

=:=numbers equal?2 + 1 =:= 3true

Numbers

Arithmetic & comparison

+-*///mod**
<>=<>==:==\=
⚠ It's =<, not <= (that looks like an arrow ⇐ in Prolog).
adult(X)    :- age(X, A), A >= 18.
teen(X)     :- age(X, A), A >= 13, A =< 19.
older(X, Y) :- age(X, A), age(Y, B), A > B.
X is 7 / 2, Y is 7 // 2, Z is 7 mod 2.X = 3.5,\nY = 3,\nZ = 1.
teen(X).X = farah ;\nfalse.
age(X, A), A < 20.X = farah,\nA = 16 ;\nX = hana,\nA = 2.
// is integer division, mod is remainder. Comparisons need both sides to be numbers (bound), otherwise: "Arguments are not sufficiently instantiated".
How Prolog searches

Backtracking: depth-first, left-to-right

Depth-first: finish one path completely before trying another.
Backtrack: on failure (or ;), undo the last choice and try the next clause.
Walk through each node. Then in SWI run the query and press ; to match the tree. In the lab, PROLOG//LAB animates this tree automatically for any query.
Rules that use themselves

Recursion: ancestor

ancestor(A, D) :- parent(A, D).                  % base case
ancestor(A, D) :- parent(A, X), ancestor(X, D).  % recursive
ancestor(ali, hana).true ;\nfalse.
ancestor(A, hana).A = danial ;\nA = ali ;\nA = siti ;\nA = aminah ;\nfalse.
Always put the base case first, and make each recursive step move closer to it, or the recursion never stops.
Two clauses: either A is directly D's parent (base), or A is parent of some X who is an ancestor of D. Trace the chain ali → aminah → danial → hana.
The workhorse data structure

Lists: [Head | Tail]

nasi_lemak
satay, laksa
HEADTAIL (also a list)
[H|T] = [nasi_lemak, satay, laksa].H = nasi_lemak,\nT = [satay, laksa].
member(satay, [nasi_lemak, satay]).true.
my_sum([10, 20, 30], S).S = 60.
my_sum([], 0).
my_sum([H|T], S) :- my_sum(T, S0), S is H + S0.
[] is the empty list. Recursion on lists: handle the head, recurse on the tail, stop at []. my_sum is in the demo file.

Real SWI-Prolog messages

Top 5 beginner errors

1 · missing full stop
likes(ali, satay) ← no "." ERROR: file.pl:1:18: Syntax error: Operator expected
✓ end every clause with . (it also swallows the next line!)
2 · uppercase predicate
?- Parent(ali, X). ERROR: Syntax error: Operator expected
✓ predicate names are atoms → lowercase
3 · program not loaded / typo / wrong arity
ERROR: Unknown procedure: parent/2
✓ consult the file · check spelling · count the arguments
4 · singleton variable (warning)
bad(X, ali). Warning: Singleton variables: [X]
✓ used only once? Probably a typo, or write _
5 · maths on an unknown
?- X is Y + 1. ERROR: Arguments are not sufficiently instantiated
✓ give Y a value first: Y = 4, X is Y + 1.
And: typing a fact at ?- asks a question. It doesn't store anything.
